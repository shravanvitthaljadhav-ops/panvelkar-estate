# V2.0 migration map — clarification addendum

- Preserve source wing labels exactly: R1-A, R1-B, R2, R3, R4. Display/sort labels may be normalized to R1A/R1B only in presentation logic; do not rewrite stored source values.
- V2.0 template library records include: id, name, category, message, fileName, locked. Runtime also manages active state via activeTemplateId. The database adapter therefore maps fileName to payment_templates.file_name.
- V2.0 unit records include otherEmail; map it to payment_units.other_email.
- Historical units may have received amounts but no reliable transaction detail. Preserve such amount in payment_units.opening_received and retain the original paymentDate only as a unit-level legacy date if supplied. Do not invent a payment transaction or date.
- Transaction-backed received amount is opening_received plus the sum of payment_transactions.amount.
- This is a documentation addendum only; no production or database change.
